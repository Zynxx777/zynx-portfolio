# Portfolio ideas for later

These ideas stay separate from the current local review so the site does not grow features without a clear job-search purpose.

## Highest value

### 1. S.M. English School case study

Add a concise case-study page with screenshots of the real site, a clear list of completed pages, the responsive decisions, and the Supabase admin sign-in prototype. Label the project as a personal, AI-assisted MVP and distinguish shipped work from planned work.

**Why it helps:** It gives a recruiter direct evidence of how the project was built and what is working. It can also make the featured project card lead to a deeper explanation than a generic spec modal.

### 2. Linux support practice notebook

Turn the Arch workstation work into two or three short, reproducible notes: how package updates were investigated, how `pactree` helped check dependencies, and what was checked before removing packages. Keep each note factual and specific to personal practice.

**Why it helps:** It shows a junior IT or Linux hiring manager how Joshua approaches a troubleshooting task without presenting home-lab practice as professional employment.

### 3. Small recruiter-ready project sheet

Create a one-page PDF that lists the current school site, portfolio, Arch Linux practice, education, and focused résumé link. Keep it text-first and ATS-readable, with source links and no unsupported metrics.

**Why it helps:** A recruiter can scan relevant evidence quickly without navigating the full 3D portfolio.

### 4. AAOS project case study

After Joshua confirms the project context, exact contribution, tools, and deliverables, add a compact case study for the Luxoft AAOS project. Keep the current academic/project-exposure label until those details establish a more specific description; useful evidence could include an approved architecture sketch, screenshots, or a short walkthrough.

**Why it helps:** Android Automotive OS and CAN concepts become easier to understand when a reviewer can see the problem, Joshua's specific contribution, and what he learned.

## Experience refinements

### 5. Bedroom atmosphere presets

Build on the existing moonlit room with a small set of quiet presets such as “Moonlight,” “Rain at the desk,” and “Warm study.” Reuse the existing lamp and rain controls, keep motion optional, and avoid adding more floating interface controls.

**Why it helps:** The room already contains a desk plant, MIDI keyboard, headphones, posters, books, rug, window, curtains, and layered lamps. Future room work can focus on atmosphere and camera composition.

### 6. Guided project walkthrough

Offer a short, optional “Start here” sequence for the school project, Linux practice, focused résumé, and contact section. Make every step dismissible and ensure the underlying page remains fully navigable by keyboard.

**Why it helps:** It makes the visual site easier to scan while keeping its creative identity.
